# 02 · SM2 签名与公钥匹配

**方向**：密码安全（国密 SM2）　**难度**：进阶　**分值**：20
**对应真题**：2025 决赛运维实操第 7 题

## 背景
某系统用国密 SM2 算法对业务数据签名，数据格式为：`M` 为字符串，`e` 为消息杂凑值，`r+s` 为签名值。
开发人员对 SM2 理解有误：**签名时直接对数据本身签名，而不是对规范要求的杂凑值 `e = SM3(ZA‖M)` 签名**。
现在拿到了 5 条签名（`signatures.json`）和 4 个公钥（`public_keys.json`）。

## 题面
1. 判断序号 1~4 的签名分别是用哪个公钥签的。
2. 第 5 条签名对应哪个公钥？它和前 4 条有什么不同？
3. 用一句话说明：规范的 SM2 签名里，`e` 应该怎么算？`ZA` 里包含哪些内容？

## 数据格式
- `public_key`：`04 || x || y`（未压缩点，65 字节 = 130 个 hex 字符）。
- `rs`：前 64 个 hex 是 `r`，后 64 个 hex 是 `s`。**是拼接，不是相加。**
- `e`：开发者记录的“杂凑值”字段。1~4 号记录的是 `SM3(M)`，第 5 条记录的是规范的 `SM3(ZA‖M)`。

## 提交格式
```
1-x、2-x、3-x、4-x；第5条=公钥x
```

## 提示
- 公钥验签就能判断签名者，**不需要私钥**。
- 直接运行 `python3 match.py` 观察每条签名用哪个公钥、哪种 `e` 能验过。
- gmssl 等库的高层 `verify` 会自动做 `ZA + SM3` 预处理，和这题的缺陷实现对不上。
