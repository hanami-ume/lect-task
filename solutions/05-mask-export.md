# 题解 · 05 脱敏导出与文件指纹

## 答案
- 被剔除：**`1003_1004_1005_1006_1007`**
- `cleaned.csv` 的 MD5：**`11aa36f7b06fcb58fbf01abeee438b67`**（SHA-256：`d9769da35d0b17c9e1d5379497cc8fffe817999a6d3bd0328789fc16f8062f39`，235 字节）

被剔除原因：
- 1003：`consent=N`（未同意）
- 1004：手机号只有 10 位
- 1005：手机号第二位是 2（不满足 `1[3-9]`）
- 1006：出生日期 `19990230` 不存在
- 1007：身份证校验位错误

## 正确的 cleaned.csv（`\r\n` 表示 CRLF）
```
id,name,phone,id_card\r\n
1001,陈**,139****1111,990000********1239\r\n
1002,刘*,138****2222,990000********4565\r\n
1008,郑**,150****8888,990000********1118\r\n
1009,冯*,133****0000,990000********3336\r\n
1010,王*,177****9999,990000********222X\r\n
```

## 思路
1. **先校验后脱敏**：脱敏会遮住号码，必须在脱敏前判断合规。
2. 身份证三重校验：`^\d{17}[\dX]$` + 第 7~14 位是合法日期 + 第 18 位校验码（GB 11643 / ISO 7064 MOD 11-2）。
3. 按 id 数值升序，脱敏（姓名留首字、手机前3后4、身份证前6后4）。
4. 导出：UTF-8 无 BOM、逗号分隔、CRLF、末尾一个 CRLF 且不留空行。
5. `md5sum cleaned.csv` / `certutil -hashfile cleaned.csv MD5`。

## 知识点
- 文件哈希针对**每一个字节**：LF/CRLF、BOM、尾部空行、编码、引号、排序，任一不同 MD5 就变——这正是综合防御第 14 题“UTF-8&CRLF、去尾部空行”的用意。
- 掩码后仍保留了身份证前 6 后 4 等，可与其他数据关联，属于**去标识化**而非匿名化。
